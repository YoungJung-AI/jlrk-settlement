## 2. JG / LR 코스트센터 라인 반전

| 문서 | 위치 | 증상 |
|---|---|---|
| Engine Oil AR 바우처 | 표지 G39/G40 | JG `64,666,800`이 LR 라인에, LR `377,155,533`이 JG 라인에 (약 3억 반전) |
| Retailer Support 바우처 | 표지 D39~D42 | D열 코스트센터 라벨(`KR02JSU300 JG`)과 실제 금액·S열 표식(`LR`)이 반대. Castrol 라인도 동일 |
| Recall Upselling | AP_input M열 | JG/LR을 브랜드 실적 무시하고 10:90 고정 배분 (M7=I7\*10% = VAT식 복사 흔적). 실제 실적 JG 34.8% / LR 65.2% |
| 표지 검증식 (AP·AR 공통) | M54/M50 | `=IF(G53=$E$27,...)` — VAT코드 셀 참조. `$E$25`(Net)이 맞음 |

**대응:**
- 시스템이 바우처 생성 시 **JG↔LR을 바르게 맞춰서** 출력 (사용자 확인 완료). Retailer Support 표지 D열 라벨도
  금액에 맞게 교정 예정 (3단계 코드 보정).
- 과거 결재본(수기 엑셀)의 반전은 **사용자가 실제 P&L과 크로스체크**할 사안. 시스템 코드 대상 아님.
- Recall Upselling 유형: 시스템 설정 `brand_split_mode = ACTUAL` 로 되어 있는지 확인 필요.

## 3. AR 거래처 코드 (customer code)

- `workshops.customer_code` (예: `KR01074MIS`) / `workshops.ar_biz_no` 컬럼은 있으나 **전부 비어 있음**.
- One DMS License / Engine Oil AR 바우처 생성에 필수. AP의 vendor code(`KRJD…`)와 완전 별개 체계.
- **충돌:** 효성 센텀 지점 — One DMS 파일에선 `KR01030MIS`, Engine Oil AR 파일에선 `KR01170MIS`. 어느 게 맞는지 확인.
- **필요:** 지점별 `customer_code` + (AP와 다를 때만) `ar_biz_no` 목록. 주면 마이그레이션으로 seed.

## 사용자에게 필요한 것 (요약)
1. 효성 센텀 사업자번호 `2548500545` 맞나? (seed `1728600556` 교체)
2. 인타이어 대구 / 위본 전주 — 상황별로 어느 사업자번호가 맞는지
3. 세금계산서를 `biz_no` 단위로 발행하도록 되돌릴지 (AJ·HS·WB 때문에). 되돌리면 Engine Oil 외 유형에 적용
4. AR 거래처 마스터 (지점별 customer code + ar_biz_no)
5. 효성 센텀 AR customer code — `KR01030MIS` vs `KR01170MIS`
