# JLRK 정산 포털 — 전체 기능 테스트 시나리오

관리자 생성 → 리테일러 정산 → 바우처까지 모든 기능을 한 번에 검증하는 순서.
각 줄 앞 `[ ]` 를 체크하며 진행. **기대 결과**가 다르면 그 줄 번호와 화면을 기록해 알려주세요.

- 운영 주소: https://jlrk-portal.github.io/
- 사전 반영 필요: `migrations/019`, `020` 실행 완료 상태여야 함 (이미 반영됨)
- 브라우저: 크롬 권장. 관리자/리테일러를 동시에 볼 거면 **일반 창 + 시크릿 창** 병행.

---

## 0. 준비물 (테스트 파일)

| 용도 | 파일 |
|---|---|
| AP 청구서 양식/원천 (Recall류) | 지점별 금액이 든 `Sheet1` 패턴 엑셀 1개 (리테일러 1곳 몫, 지점 여러 개) |
| AP 바우처 템플릿 | `AP without PO` + `AP_input reqeust` 시트가 있는 xlsx |
| 세금계산서 PDF | 아무 PDF 1장 (테스트용) |
| AR 원천 엑셀 (Engine Oil AR류) | 지점 + 금액 + Jaguar/Landrover 컬럼 |
| AR 바우처 템플릿 (One DMS / Engine Oil AR) | 각 유형별 원본 xlsx |
| Engine Oil 3종 | `CouponClaim_현황.xlsx`, `쿠폰북정산내역_*.xlsx` + 바우처 템플릿 3개 |

메일 발송까지 보려면 리테일러 계정 중 **1곳 이상은 실제 수신 가능한 이메일**로.

## 1. 계정 · 로그인 · 권한

1. [ ] 관리자 이메일/비번으로 로그인 → **대시보드**로 진입. 좌측 메뉴 6개(대시보드/정산 유형 관리/회차 관리/리테일러 관리/계정 관리/활동 이력) 노출.
2. [ ] **계정 관리** → 리테일러 계정 신규 생성: 이메일 `aj-test@example.com`, 초기비번(8자↑), 역할 RETAILER, 소속 리테일러 = 아주(AJ). → 목록에 뜸.
   - 기대: `manage-user` Edge Function 호출 성공. 실패 시 "service_role 키를 찾을 수 없습니다" 등 에러 확인.
3. [ ] 같은 방식으로 **효성(HS)**, **위본(WB)** 테스트 계정도 생성 (그룹 내 사업자번호 갈리는 곳 검증용).
4. [ ] 계정 목록에서 한 계정 **비밀번호 재설정** → 새 임시비번 발급됨 (must_change_password 표시).
5. [ ] 로그아웃 → 방금 재설정한 계정으로 로그인 → **비밀번호 변경 화면 강제** 노출. 새 비번 설정 후 정상 진입.
6. [ ] 계정 목록에서 한 계정 **비활성화** → 로그아웃 후 그 계정 로그인 시도 → 로그인 후 즉시 로그아웃되거나 차단.
7. [ ] 다시 **활성화** → 정상 로그인.
8. [ ] (격리) 아주 계정으로 로그인한 상태에서 효성 회차/청구가 **안 보이는지** (뒤 단계에서 재확인).

## 2. 마스터 데이터 (리테일러 · 지점)

9. [ ] **리테일러 관리** → 아주(AJ) 편집: 대표자명, 알림 이메일 입력, 대표 사업자번호가 `2148800795`(한남 기준)로 보이는지. 저장.
10. [ ] 리테일러 목록에서 placeholder 이메일인 곳에 **경고 표시** 뜨는지.
11. [ ] 지점 관리(리테일러 상세 안) → 효성 센텀(HS-BC) 편집: 사업자번호 `2548500545`, AR 사업자번호 공란(=AP동일), **Customer code `KR01170MIS`** 표시 확인.
12. [ ] 인타이어 대구(EN-DG): AP 사업자번호 `5028540484`, **AR 사업자번호 `5148147707`** 둘 다 표시.
13. [ ] 어느 지점을 **대표지점으로 지정** → 저장 → 다시 열어 체크 유지. 다른 지점을 대표로 지정하면 이전 대표 자동 해제.
14. [ ] Customer code 미입력 지점(서대구)이 목록에 **주황색 "미입력"** 으로 뜨는지.
15. [ ] 리테일러 **신규 추가** → 저장 → 목록 반영 → (테스트 후) 비활성화.
16. [ ] 지점 **신규 추가**(예: 천일 천안 CH-CA, vendor code/ customer code 입력) → 저장.
    - 기대: 이후 정산에서 이 지점이 매칭됨.

## 3. 정산 유형 관리 (Phase 1)

17. [ ] **정산 유형 관리** → [+ 새 유형] → **AP-UPLOAD 유형** 생성:
    - 유형코드 `RECALL_UPSELL_T`, 유형명 `Recall Upselling(테스트)`, 방향 **AP**, 주기 분기, 청구단위 **지점**
    - 마감 규칙(익월 10일 18:00 등), 부가세 별도, 절사 FLOOR, 상한 없음
    - 알림 **즉시**, 리마인더 `3,1`
    - 조기마감 체크, 마감 후 개별 재오픈 허용 체크
    - 대상 리테일러: 아주·효성·위본만 선택
    - 바우처 설정: GL `700050800`, LR 코스트센터 `KR02LSU300`, JG `KR02JSU300`, 설명 `Recall Campaign Upselling Program`
    - 예산 구분 지정
    - 청구서 양식(xlsx) 업로드, 바우처 템플릿(xlsx) 업로드
    - 저장 → 목록에 뜸.
18. [ ] 유형 다시 열어 **모든 값이 저장돼 있는지** 확인. 한 필드 수정 후 재저장.
19. [ ] [+ 새 유형] → **AR-UNIT 유형**(One DMS류): 방향 **AR**, 산출방식 **수량 × 단가**, 단가 `109329.6667`, 금액 계상 단위 **법인 대표지점**, 부가세 `A1: 10%`, JG/LR 고정 JG 0.10, GL `605030101`. 저장.
20. [ ] [+ 새 유형] → **AR-UPLOAD 유형**(Engine Oil AR류): 방향 AR, 산출방식 **원천 엑셀 업로드**, 부가세 `A0: 0%`, 계상 단위 **지점별 개별**, JG/LR **원천 실적대로**, GL `702030000`, 원천 파싱 규칙 JSON `{"sheet":"...","workshop_col":"Workshop","amount_col":"Total","jg_col":"Jaguar","lr_col":"Landrover"}`. 저장.
21. [ ] [+ 새 유형] → **SYSTEM 유형**(Engine Oil 3종): 방향 AP, 산출방식 **시스템 산출**, 원천 파싱 규칙 JSON `{"preset":"ENGINE_OIL_3V"}`, 중복 판정 키 `차대번호, 쿠폰사용 참조번호, 쿠폰번호`, 상태 컬럼 `클레임상태`, 대상 상태값 `전송`. 저장.
22. [ ] 유형 하나 **비활성화** → 회차 개설 화면 유형 목록에서 빠지는지. 다시 활성화.
23. [ ] 회차가 없는 임시 유형 하나 만들어 **삭제** → 목록에서 사라짐.

## 4. AP 정산 전체 흐름 (Phase 2~4) — `Recall Upselling(테스트)` 유형

### 4-1. 회차 개설 · 청구 접수
24. [ ] **회차 관리** → [+ 새 회차] → 유형 `Recall Upselling(테스트)`, 기간 라벨 `FY27 Q1`(→ 회계연도/분기 자동 채움), 청구 마감일시(가까운 시간으로) → 저장 → 상태 **준비중(DRAFT)**.
25. [ ] 회차 클릭 → 상세. [리테일러에게 청구 요청 시작] → 대상 3개사에 지점별 청구 항목 자동 생성, 상태 **접수중(OPEN)**.
    - 기대: 실메일 계정엔 "청구 요청 + 마감일" 메일 수신.
26. [ ] 상세에 **제출 현황판**(지점 그리드, 전부 미제출 색) 표시.

### 4-2. 리테일러 제출 (시크릿 창 = 아주 계정)
27. [ ] 아주 계정 로그인 → **내 정산** 에 `FY27 Q1` 카드. 회차 하나 = 카드 하나, 안에 지점 3개 테이블.
28. [ ] 카드 상단 **청구서 양식 다운로드** 링크 동작.
29. [ ] 엑셀 파일 업로드 → 지점별 금액 칸 **자동 채움**. "3개 중 N개 매칭" 안내. 천단위 콤마 포맷.
30. [ ] 한 지점 금액 수동 수정 → 하단 **합계 실시간 갱신**.
31. [ ] 한 지점 [청구없음] 클릭 → 확인창 → 0원 처리.
32. [ ] [전체 제출] → 매칭된 지점만 제출, 빈칸은 제외. 상태 배지 "제출됨".
33. [ ] 제출된 지점 옆 [제출취소] → 확인창 → 금액·파일 초기화, 입력칸 복귀. 관리자 현황판에서 "미제출"로 되돌아감(다음 단계에서 확인).
34. [ ] 새 엑셀로 재업로드 → 취소했던 지점만 다시 채워짐(제출완료 지점은 불변). [전체 제출].

### 4-3. 관리자 검토 · 확정
35. [ ] 관리자 창 새로고침 → 현황판에 아주 지점들 "제출됨". 파일 다운로드 동작.
36. [ ] [미제출 리테일러 독촉] → 효성·위본에 리마인더 메일 (실메일 계정만).
37. [ ] (효성·위본도 27~32 반복해 제출) 또는 조기마감 테스트: 전원 제출 시 조기마감 옵션 동작 확인.
38. [ ] [지금 마감] → 확인창 → 상태 **검토중(CLOSED)**.
39. [ ] 검토 대기 표: 지점별 **청구금액 / 직전 회차 / 확정금액** 컬럼. 한 건 **[승인]**(청구금액 그대로).
40. [ ] 한 건 **[수정승인]**: 확정금액 다르게 입력 + 코멘트 필수 + 파일 첨부 → 저장. (코멘트 없이 저장 시 막힘 확인)
41. [ ] 한 건 **[반송]**: 사유 + 제안 금액 + 파일 첨부 → 저장.
42. [ ] [선택 일괄 승인] 으로 나머지 처리.

### 4-4. 반송 재청구
43. [ ] 리테일러 창(아주) → 반송된 지점만 **입력칸 + [재청구] 버튼** 별도 표시. 관리자 제안금액·사유·첨부파일도 보임.
44. [ ] 금액 수정 + 새 파일 → [재청구].
45. [ ] 관리자 창 → 그 건이 다시 검토 대기(SUBMITTED)로. **재승인** 처리. 이전 반송 사유는 사라짐.

### 4-5. 확정 공지 · 세금계산서
46. [ ] 관리자: **세금계산서 발행일**(필수) 지정, 계산서 마감일시(선택) → [확정금액 공지] → 상태 **확정공지(CONFIRMED)**.
    - 기대: 리테일러 전체에 "최종금액 + 계산서 요청" 메일.
47. [ ] 리테일러 창(아주): 카드에 **청구금액 / 확정금액 2줄** 표시. 관리자 코멘트·수정파일 링크.
48. [ ] 소속 지점이 **전부 승인**되면 하단에 **세금계산서 제출 영역** 노출 (부가세 입력 + PDF 첨부, **1건만**).
    - 아주는 한남 기준 사업자번호 → **리테일러당 계산서 1장**.
49. [ ] 부가세 입력 + PDF 업로드 → 제출. "접수완료" 배지.
50. [ ] 관리자: **계산서 접수 현황**(공급가액 / 부가세 / 일치·확인필요 배지). 부가세를 공급가×10%와 다르게 넣어 "확인필요" 배지도 테스트.
51. [ ] (효성·위본도 계산서 제출)
52. [ ] [계산서 전원 접수 확인] → 상태 **계산서접수(INVOICED)**.

### 4-6. 바우처 생성
53. [ ] 상세에 **[바우처 생성]** 섹션. 리테일러별 대표 지점 드롭다운 확인.
54. [ ] [바우처 생성] 클릭 → 진행 문구 → **ZIP 다운로드**:
    - `바우처.xlsx` (표지 `AP without PO` + `AP_input reqeust` + 리테일러별 `Tax Invoice_*` 이미지 시트)
    - `바우처_표지.pdf`
    - `raw_data_통합.xlsx`
55. [ ] 엑셀 열어서: 경고 없이 열리는지, 표지 Invoice Date·GL 라인·Total, input 시트 지점별 금액(M/N), 브랜드 배분(raw 시트에서 자동 or ⚠️확인필요), 계산서 이미지 삽입 확인.
56. [ ] [완료 처리] → 상태 **완료(VOUCHERED)**.

## 5. AR 정산 흐름 (Phase 6)

### 5-1. AR-UNIT (One DMS류, 수량×단가)
57. [ ] 새 회차 개설(AR-UNIT 유형, `FY27 Q1`). AR은 청구 마감일 대신 이의제기 마감.
58. [ ] 상세 → [청구 대상 생성] → 대상 리테일러 claims 생성.
59. [ ] DRAFT 표에 **수량 컬럼** 노출(산출방식이 수량×단가라서). 지점별 수량 입력 → **청구금액 = 수량 × 109329.6667** 자동 계산(원 단위 반올림), 청구금액 칸 readonly. [저장].
60. [ ] 이의제기 마감일시 지정 → [리테일러에 청구 공지] → 상태 **공지됨(PUBLISHED)**. 메일 발송.
61. [ ] 리테일러 창: AR 카드 = 청구금액 크게 표시. [청구금액 확인] 또는 [이의제기].
62. [ ] 한 리테일러: [이의제기] → 요청금액 + 사유(필수) + 근거 파일 → 제출. 배지 "이의제기 검토중".
63. [ ] 다른 리테일러: [청구금액 확인] → "확인완료".
64. [ ] 관리자: 이의제기 처리 표 → [승인(금액수정)](요청금액 반영) / [반려](사유). 각각 테스트.
65. [ ] [최종 확정] → 상태 **확정(FINALIZED)**. (또는 이의제기 마감 지나면 자동 확정 확인)
66. [ ] AR 바우처 생성 버튼 → xlsx 다운로드. `AR_input reqeust` 행이 **customer code로 매칭**돼 금액·VAT·JG·LR 배치, 부가세는 유형 설정 따름(A1=10%). 시트명 끝 공백 처리. 미배치 리테일러 하단 표시.

### 5-2. AR-UPLOAD (Engine Oil AR류, 원천 자동집계)
67. [ ] 새 회차(AR-UPLOAD 유형). [청구 대상 생성].
68. [ ] DRAFT에 **원천 엑셀 업로드** 칸. AR 원천 파일 업로드 → 지점 라벨 매칭 → 리테일러별 금액·JG·LR **자동 채움**. 미매칭 지점 경고. 현황표 하단 **JG+LR 일치 검증 배지**.
69. [ ] [리테일러에 청구 공지] → 이후 5-1의 61~66과 동일 흐름.
70. [ ] AR 바우처: 부가세 A0=0% → VAT 0 계산. 브랜드 배분은 저장된 jg/lr 사용.
